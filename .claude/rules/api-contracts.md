# API Contracts

Per [ADR-016](../planning/adr/ADR-016-api-contract-workflow.md), every HTTP endpoint is defined as a Mongoose schema in `../models/` **before** FE or BE implementation begins. The schema is the single source of truth for BE validation, FE types, OpenAPI documentation, mock data, and contract tests.

## 🚦 STOP — contract before code (binding gate)

**No controller and no FE api-slice may be written until the contract exists and is merged.** This is the rule that removes FE/BE conflicts (one source of truth, no hand-written interfaces) and unblocks the FE (it builds against the generated MSW mock instead of waiting for the API).

The sequence is non-negotiable:

1. **Contract first** — `/contract <domain> <feature>`, fill in real Mongoose shapes, merge the small contract PR. This is the *only* step that blocks both sides, and briefly.
2. **FE and BE branch in parallel** — FE off the MSW handler, BE off the schema. Neither waits for the other; neither defines the shape.
3. **Cutover** — FE drops the MSW handler once BE merges.

Enforcement (do not bypass any layer):

- **Harness hook** — `.claude/hooks/contract-first-gate.sh` rejects any write to a `*.controller.ts` or FE `*-api.ts` that does not consume `../models/`. Escape hatch for external anti-corruption proxies only: a `// contract-exempt: <reason>` line.
- **`/implement`** — Phase 0 halts if a touched endpoint has no merged contract.
- **Code review** — a controller or FE api-slice in a PR without a corresponding merged contract is a blocking review comment.

If you find yourself hand-writing a request/response `interface`, or building a screen that calls a not-yet-built endpoint without an MSW handler, you have skipped the gate — stop and run `/contract`.

## Contract / implementation separation (binding)

The contract is its own deliverable. **A contract change lands as its own PR, merged before the FE/BE code that consumes it.** This is the separately-mergeable unit that unblocks parallel FE/BE work and gives a standalone, reviewable contract diff (the `openapi.json` change).

- **Contract files** = `server/models/src/**`, `server/openapi.json`, `server/src/openapi/**`.
- **Implementation files** = consuming code: `server/src/**` (except `openapi/`) and `clientApp/src/**`.
- **Default:** a PR contains *either* contract files *or* implementation files — not both.

**A standalone contract PR is REQUIRED when:** FE and BE are built by different people/in parallel; the endpoint has more than one consumer; or the change is breaking (rename/remove a published schema).

**Collapsing contract + implementation into one PR is acceptable ONLY when ALL hold:** the change is a small, additive, *optional* field; built solo and sequentially; and has no other consumer. In that case, justify it with a `contract-collapse-ok: <reason>` line in a commit message.

**Enforcement:** the `contract-separation` CI job (`scripts/ci/check-contract-separation.mjs`) fails any PR that mixes the two sets unless a `contract-collapse-ok:` marker is present. This is the PR-level complement to the per-edit `contract-first-gate.sh` hook (which only enforces that controllers / FE api-slices *consume* the shared schema, and cannot see a whole PR).

## Source of truth

| Artifact | Source | Generated by |
|---|---|---|
| BE request/response validation | Mongoose schema in `server/models` | `ZodValidationPipe` + parse-on-the-way-out |
| FE TypeScript types | Same Mongoose schema | `z.infer<typeof Schema>` |
| OpenAPI document | Same Mongoose schema (with `.openapi()` metadata) | `server/src/openapi/registry.ts` → `openapi.json` |
| Mock data | Same Mongoose schema | `@anatine/zod-mock` factories in `server/models/src/<domain>/*.mocks.ts` |
| MSW handlers | The mock factory above | `server/models/src/<domain>/*.handlers.ts` |
| Contract tests | Same Mongoose schema | `*.controller.spec.ts` parses controller output |

## Always

- Add the Mongoose request and response schemas in `server/models/src/<domain>/<feature>.schemas.ts` **before** writing the controller or the FE screen
- Decorate every public schema with `.openapi('SchemaName', { description, example })` so the generated `openapi.json` is human-readable
- Register every endpoint in `server/src/openapi/registry.ts` and run `npm --filter @ticketing-application/api openapi:emit` so the committed `openapi.json` matches the schemas
- Parse the controller response with the response schema before returning (`return ResponseSchema.parse(response)`) — turns drift into a loud error
- For every endpoint, ship a mock factory (`<feature>.mocks.ts`) using `generateMock(Schema)` plus selective overrides
- For every endpoint, ship an MSW handler (`<feature>.handlers.ts`) that returns the mock factory output — these become FE test fixtures
- Write a controller spec that parses the real response with the shared schema (`SomeController.spec.ts`)
- Treat the `openapi.json` diff as a code review artifact — it is the human-readable view of the contract change

## Never

- Hand-write a TypeScript `interface` for a request or response shape — use `z.infer<typeof Schema>` instead
- Define the same payload shape twice (e.g., once in a controller DTO and once in a Mongoose schema) — there must be one source
- Skip the `.openapi()` metadata — the generated OpenAPI doc loses descriptions and becomes useless
- Edit `server/openapi.json` by hand — it is generated, CI will diff it
- Build a controller without registering its path in `openapi/registry.ts`
- Throw away an MSW handler after the BE endpoint lands — keep it as a test fixture

## Ask First

- Adding a new field to an existing schema that has dependent consumers (the contract change may require coordinated FE/BE releases)
- Removing or renaming a published schema — breaking changes need a versioning decision
- Adding a non-Mongoose validation layer at the controller (e.g., `class-validator` DTOs) — duplicates the source of truth
- Skipping the contract PR step for a "quick fix" — discuss the trade-off explicitly

## Workflow for adding an endpoint

1. **Contract PR** (single, small):
   - Add Mongoose schemas in `server/models/src/<domain>/<feature>.schemas.ts` with `.openapi()` metadata
   - Add mock factory and MSW handler files alongside the schema
   - Register the path in `server/src/openapi/registry.ts`
   - Run `npm --filter @ticketing-application/api openapi:emit`
   - Add a self-test for the MSW handler (boots `setupServer`, fetches, parses with the schema)
   - Merge to `main` — this is the only step that blocks both FE and BE
2. **FE branch** (parallel):
   - Import `z.infer<typeof ResponseSchema>` for types
   - Bootstrap MSW with the new handler in dev runtime
   - Build the screen against MSW
3. **BE branch** (parallel):
   - Implement the controller and use case
   - Use `ZodValidationPipe(RequestSchema)` for request validation
   - End the controller with `return ResponseSchema.parse(response)`
   - Add a controller spec that parses the controller output with the shared schema
4. **Cutover**: when the BE merges, the FE removes the handler from the dev runtime (the file stays as a Karma + Jasmine fixture)
